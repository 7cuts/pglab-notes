# Основная Идея
Пакет -- структура `sk_buff`, которая аллоцируется при получении пакета из сетевой карты или при вызове системных вызовов для отправки из пользовательского пространства.  Причём структура может как *клонироваться*, так и *копироваться*.

**Клонирование** (`skb_clone()`) создаёт новый `sk_buff`, который разделяет с текущим один буфер данных. Полезно, когда нужно отпарвить один и тот же пакет нескольким получателям (например, сокеты + форвардинг). Бит `cloned` выставлен в единичку в обоих пакетах
**Копирование** (`skb_copy()`) создаёт полную и независимую копию пакета. 
(источник: [kernel-internals-net > Networking > sk_buff: The network buffer#Cloning and sharing](_sources/kernel-internals-net.md)).

> Если мы планируем отслеживать пакет, то важно следить за его копированием и клонированием. 
# Путь
## Отправка
Здесь я указываю списком, но по факту следующая пункт может вызываться в предыдущем

### Transmission Layer: L4 to L3
1. Socket Layer - системный вызов `write()` или `sendto()`.  В статье рассматривается только `write()`.
2. `sock_sendmsg()`
3. Из `task_struct` получаем котнрольное сообщение, содержащее PID, UID, GID. С этой информацией проходим всякого рода проверки безопасности (например, SELinux)
4. `tcp_sendmsg()` Ждёт, когда tcp соединение будет установлено
5. `tcp_write_queue_tail()`. Биллдит TCP хедер и кладёт данные из юзер спейса в `sk_buff`. *Видимо, эта функция пишет пакет в write_queue()?*
6.  Если данные укладываются в существующий буфер, то вызывается `skb_add_data_nocache()`, иначе создаём новый буфер. Выставляем `transport_header` на начало построенного хедера.
7. Билдим хедер уровня L3 (IP). 
8. `tcp_write_xmit()` заводит *retransmission timers* 
9. `tcp_transmit_skb()` читает очередь на запись, в которую мы до этого положили пакет и отправляет их на уровень L3 через `queue_xmit()`

### Internet Layer: L3 to L2

1. ``__ip_queue_xmit()``. Определяем, куда роутить пакет. Если указан `sk_buff->skb_refdst`, то делать этого не надо. 
2. **Роутинг**. 
	1. Пытаемся понять адресата через поля `sk_buff` (если до этого на сокет пришёл какой-то IP пакет, то мы точно знаем, куда отправлять)
	2. Если не поняли, то смотрим **Forwarding Information Base (FIB)** - табличка, которая генерируется по таблице ip роутинга (???)
3. `ip_options_build()` - заполняем ip-опции. Также триггерит состояние `LOCAL_OUT` у фаервола `netfilter`.
4. `dst_output()` вызывает роутинг-функцию по указателю
5. **Состояние POST_ROUTING**. Вызывает `NF_INET_POST_ROUTING` hook. Он фрагментирует пакет, если размер превышает Maximum Transmission Unit (MTU)
6. `INET_LOCAL_OUT` hook. Затем `ip_output()` вызывает `ip_finish_output()`. Эта штука проверяет, что в `sk_buff` влезет MAC header. 
7. Остаётся только определить MAC-адрес получаелся. (функция `neigh_resolve_output()`). Для этого исползуется ARP (address resolution protocol). 
8. В конце создаём Ethernet header и добавляем его в `sk_buff`
### Ethernet Layer: L2 to L1

1. `dev_queue_xmit()` выставляет поле `mac_header` в `sk_buff`
2. `tc_egreses`. Добавляет пакет в очередь *queue_discipline* (`qdisc`). 
3. `__qdisc_run()` достаёт из очереди пакеты. 
4. Постпроцессинг в `validate_xmit_skb()` (чексуммы, VLAN теги)
5. Добавляем пакет в кольцевой буфер на отправку (TX) на сетевой карте.

## Получение
### L1 to L3
1. Сетевая карта получает пакет, кладёт его в память через DMA и посылает прерывание. 
2. Ядро аллоцирует `sk_buff`
3. Ядро удаляет ethernet header  как только пакет можно отправить на L3 уровень
4. `netif_receive_skb()`. Клонирует `sk_buff` (не копирует!) 
5. Попадаем в TAP интерфейс (TAP позволяет виртуальным машинам и хосту находиться "в одной сети", а также перенапарвлять пакеты в соответствии с их VLAN тегом).
6. `rx_handler()` не понял когда вызывается. в статье пишут: *Furthermore, when the interface has a physical master, i. e., it is a virtual interface or part of a network bridge, rx_handler() steals the packet. rx_handler() also sets the network_header field of the sk_buff. Finally, it calls the IPv4 protocol handler function ip_rcv().*. Ещё эта функция заполняет ip хедер
### L3 to L4
1. `ip_recv()`. Проверяет, что mac адрес пакета совпадает с адресом текущей машины, иначе дропает его. Также проверяет чексумму ip-пакета
2. Запуск `PRE_ROUTING` правил у netfilter. (`NET_INET_PREROUTING` hook). Кладём функциональный указатель `ip_rcv_finish()`, которую вызывает по выходу из хука
3. Если есть *network layer master device*, то отправляем `sk_buff` в его хендлер.
4. Проверяем ip опции через `ip_recv_options`
5. Вызваем выбранную ранее функцию роутер, вызывая `dst_input()`. Далее у нас 3 варианта развития событий
	1. `ip_forward`:  если пакет адресован не этой машине. перенаправляет пакет
	2. `ip_local_deliver`: если мы конечный адресат (указаны в dst_ip пакета)
	3. `ip_mr_input` для  пакетов, отправленных на мультикаст адресов
6. `ip_local_deliver` дефрагментирует ip пакета через `ip_defrag()`, придерживая пакеты до момента, пока они не будут полностью собраны в один
7. Событие `NF_INET_LOCAL_IN` триггерится. Оно возвращает `ip_local_deliver_finish()`. Эта штука удаляет ip хедер из `sk_buff`.
8. Отпарвляем пакет на уровень `L4` Через `tcp_v4_recv()`. 

### L4 layer
1. `tcp_ipv4_recv()`. Сейчас указатель на хедер в `sk_buff` 
2. `pskb_may_pull()` валидирует TCP хедер. (чексумму). 
3. ищем сокет-получатель через `__inet_lookup_skb()`. Эта функция записывает пакте в receive queue на сокете и посылает сигнал о новых данных (`SIGIO`, `SIGURG`) - для поллинга.

#### Машина состояний TCP
- `TCP_NEW_SYN_RECV` - это новое подключение. Фильтруем в `tcp_filter()`
- `TCP_TIME_WAIT` - отбрасываем все пришедшие TCP сегменты

 Есть 2 пути, *короткий* и *быстрый*. 
 При коротком мы ждём, пока соединение не перейдёт в состояние `TCP_ESTABLISHED`, в `tcp_v4_do_recv()`, а дальше вызываем `tcp_rcv_established`, который уже обрабатывает пакет как при коротком, так и при быстром пути. Ядро, конечно, всегда старается выбирать быстрый путь, когда это возможно.
