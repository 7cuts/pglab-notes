### Распределение байтов при отправке через tcp сокет

Давайте напишем ещё одну программу, которая показывает распределение количества байтов, которые отпарвляются ядром на tcp-сокетах.

- `hist` - встроенная в стандартную библиотеку функция, которая строит гистограмму по аргументу 
- `@bytes` - bpf-карта, куда мы записываем данные, чтобы потом передать их в user-space
- `arg3` - это параметр `size` функции `tcp_sendmsg`. Но откуда мы взяли этот `arg3`? Для этого пишем `bpftrace -lv 'kprobe:tcp_sendmsg'`, чтобы посмотреть подробную (**v**erbose) информацию о нашей пробе.  

```c
kprobe:tcp_sendmsg
{
	@bytes = hist(arg3);
}
```
![tcp_send_hist.bt](/bpftrace/tcp_send_hist.bt)

Но как понять, какую **пробу** использовать? А здесь, к сожалению, нужно копать в ядро и разбираться, как устроены сокеты. Имея какое-никакое представление о сетевом стеке линукса, нужную функцию можно найти за 10 минут, но исходники линукса, по моему мнению, имеют очень высокий порог входа... 

Кстати, мы можем добавить фильтрацию по PID процесса, для которого мы хотим выполнять нашу программу. *Событие будет срабатывать на каждый `tcp_sendmsg`, но действия буду выполняться только при выполнении условия фильтраци*

```sh
sudo bpftrace ./tcp_send_hist.bt -p <PID> 
```

**Вывод**


#### Минусы такого подхода
- в другой версии ядра функция может иметь другое название / аргументы поменены местами / изменены типы данных
- надо очень глубоко погружаться в исходники, чтобы найти хорошую точку для отслеживания
